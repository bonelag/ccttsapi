- Package: `capcut-tts-api` version 1.0.0, Python >=3.9, declared dependency `requests>=2.25.0`; console entry point `capcut-tts-api = capcut_tts_api.cli:main`. Core exports include CapCutClient, DeviceConfig, UploadResult, SubtitleResult, voice/timing models, and exception classes.
- Configuration: base URL `https://editor-api-sg.capcutapi.com`; default device profile identifies CapCut desktop 8.7.0, Mac platform, Vietnamese locale/region. DeviceConfig accepts defaults, a dictionary, or JSON-file configuration. Core uses device identity and request signatures; there is no OAuth/login flow in the inspected code.
- `client.py`: CapCutClient owns a requests session, resolves voice_type/resource_id by loading Voice.json, builds signed JSON request triples `(url, headers, body_text)`, creates and polls TTS/STT tasks, parses audio URLs/subtitles, downloads audio, and delegates media upload to VODUploader. Explicit voice resource ID takes precedence during catalog resolution. Unknown voices fall back to supplied strings and default counterpart values rather than validation errors.
- TTS flow: `generate_speech` -> `create_tts_task` -> `build_tts_new_request` -> POST `/lv/v1/common_task/new` -> poll `/lv/v1/common_task/query` using task ID/token -> `extract_speech_urls` reads `payload.audio_subtitles[].speech_url` -> `download_file`. Inner req_key is `sami_text_to_speech`, task_version v3. Each input string becomes one SSML voice block; batch inputs share one task with need_merge_voice=False. Text is XML-escaped. WAV requests append a trailing space when absent, intended by the code to avoid old MP3 server cache entries. Core defaults to MP3 and voice BV074_streaming.
- Signing in `signer.py`: compact UTF-8 JSON; x-ss-stub is MD5 of the exact serialized body. The HTTP sign header is MD5 of a fixed-format string using the endpoint suffix, app version, device-time, and tdid. Inner TTS payload sign is Base64 of RSA PKCS#1 v1.5 public-key encryption of app/device identifiers, creditDisable, MD5(SSML), and extra_info. This is public-key encryption, despite signature terminology in docstrings. RSA public key parsing, padding, and modular exponentiation are implemented with the standard library. VOD request authorization uses an AWS4-HMAC-SHA256-style canonical request, region `sdwdmwlll`, service `vod`.
- STT flow: `transcribe_file` -> upload_audio/VODUploader -> POST `/lv/v1/upload_sign` for temporary VOD credentials -> ApplyUploadInner -> binary transfer -> finish -> CommitUploadInner -> UploadResult (vid, md5, duration) -> common_task/new with req_key `cc_audio_subtitle_asr` and cap_json -> poll common_task/query -> extract_subtitles/SubtitleResult with sentence and word timings. Duration defaults to 10,000 ms if unavailable. The upload implementation reads the entire file into memory and sends one part (part_number=0), despite chunked-upload wording.
- Polling accepts status `success`/`succeed`, raises on `failed`, otherwise waits until timeout. SDK has no built-in retry/backoff. Per-request HTTP timeout is 60 seconds for task methods; the polling timeout begins after create/upload and cannot strictly cap total operation duration. HTTP checking handles non-JSON and HTTP >=400, but does not inspect application-level error codes in HTTP-200 responses.
- Audio download: buffers the whole response; for a `.wav` destination with bytes not starting RIFF, attempts ffmpeg conversion to 24kHz mono when ffmpeg is installed. Without ffmpeg, it writes the original bytes under the requested suffix. Existing RIFF content is not normalized or fully validated. Downloads write directly to the destination.
- Voice catalog: Voice.json currently loads 129 records, of which 24 match vi-VN. list_voices loads a local catalog on each call; it does not fetch a live CapCut catalog. Default path is the package parent's Voice.json. Current setuptools configuration only discovers package directories and does not explicitly bundle this root-level JSON for wheel installations.
- REST wrapper `api.py`: FastAPI, shared CapCutClient, permissive CORS, default host 0.0.0.0/port 8080 with local free-port search. Routes: `/` (HTML demo), `/health`, `/v1/models`, `/v1/models/{model_id}`, POST `/v1/audio/speech`, POST `/v1/audio/transcriptions`. It imports the ten-voice display table/resolver from dataset.voice as a runtime dependency. Speech model names other than tts-1/tts-1-hd override the voice field; resolution exceptions silently select Nhỏ Ngọt Ngào. Generates at native rate 1.0, downloads the first speech URL, then uses ffmpeg atempo and conversion for requested speed/format. The long-text split comment has no splitting implementation in this handler.
- REST limitations observed by inspection: async endpoint bodies call synchronous requests/polling/subprocess operations directly and therefore block the event loop; no endpoint API-key validation is implemented. response_format is unconstrained, and ffmpeg missing/failure returns original bytes while the response still advertises the requested format. Raw PCM lacks explicit ffmpeg muxer/sample settings. Transcriptions implement text and SRT; vtt enters the conditional but falls through to JSON. Model detail returns a model object for arbitrary IDs. Speech download errors may leave its temporary file because cleanup is not in a finally block. These findings were not fixed or exercised against a live server.
- Gradio wrapper `app.py`: default port 7860, voice selection/custom voice, TTS with optional punctuation-based text splitting (soft 250-character limit), batch generation, ffmpeg concat, speed/volume processing, STT with SRT output, and local catalog search. It uses a shared CapCutClient and the same dataset.voice resolver. A single long sentence can exceed the split limit. TTS temporary directories are not explicitly cleaned up. Gradio launch binds 0.0.0.0; public share is optional.
- CLI supports upload-audio, tts-new/query, stt-new/query/file, list-voices, device JSON, and request dry-run. It does not expose audio_format. stt-file uploads and creates a task without polling. `--dry-run` is checked after the upload-audio/stt-file upload branch, so those modes can still upload when the flag is passed.
- Packaging notes: FastAPI, uvicorn, python-multipart, Gradio, and ffmpeg used by wrappers/features are not declared dependencies in pyproject.toml. README is partly stale (dataset paths, concurrency limits, license badge differs from project metadata).
- Offline verification only: AST-parsed all 14 package/wrapper/example Python files successfully. Imported the SDK and loaded catalog (129 total, 24 Vietnamese). Built two-segment MP3 and WAV requests, parsed SSML as XML, checked voice-block counts and x-ss-stub against MD5(body). Built STT payload with expected 12,500 ms duration and both TTS/STT query requests with correct req_key values. All checks passed. Closed the test session.
